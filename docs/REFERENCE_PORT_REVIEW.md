# Сверка с Android/PC-проектом Sonic Generations

**Обновление:** после этого обзора пользователь предоставил полный аудит XEX.
Недостающая таблица переменных теперь известна из этого отчёта, а не из
внешнего репозитория: [результат](OBSERVED_TITLE_IMPORTS.md).

Проверенный источник: [Player124413/Sonic-Generations-recomp-android-and-pc-edition](https://github.com/Player124413/Sonic-Generations-recomp-android-and-pc-edition/tree/a163e7d5cb9464056d8e34ab55f84fe38459a979),
коммит **a163e7d5cb9464056d8e34ab55f84fe38459a979**.

Ограничение: **не использовать Rexglue**. В наш проект не добавлены его SDK,
сабмодуль, зависимости, сгенерированные тела функций или патчи. Зафиксированы
только наблюдаемые метаданные и результаты независимой проверки нашего PPC.

|---|---|
| Image base / size | `0x82000000` / `0x1C40000` — совпадают |
| Code base / size | `0x82480000` / `0x1215200` — совпадают |
| Именованные импорты функций | Все **219** пар «адрес thunk, имя» совпадают; отличий нет |
| Forced landings | Все **22** адреса из внешнего TOML уже имеют метки и переходы к ним внутри функций нашего PPC |

Источники: `port/generated/default/sonicgenerations_pch.h`,
`port/generated/default/sonicgenerations_init.cpp`,
`port/sonicgenerations_forced_landings.toml` в зафиксированной ревизии.
Совпадение этих параметров **не доказывает побайтовую идентичность XEX/TU**.

Добавлен офлайн-тест `tests/test_reference_title_metadata.py`. Он проверяет
параметры образа, количество и SHA256 нормализованного списка импортов, а также
наличие перехода и метки в одной функции для каждого из 22 адресов. Эталон —
`tests/fixtures/reference_title_metadata.json`; тест не скачивает и не запускает
Rexglue. Запускается через CTest и workflow **Title import inventory**.
Это структурная проверка, не доказательство корректного поведения переходов.

## Что нельзя считать готовой реализацией для переноса

- `port/src/sonicgenerations_app.h` содержит тонкую оболочку `rex::ReXApp`;
  перечисленные хуки настройки оставлены комментариями. Инициализация ядра и
  рендеринга делегирована SDK, а не реализована отдельно для этой игры.
- `sonicgenerations_register.cpp` регистрирует адреса функций. Это не таблица
  переменных XEX. В изученных manifest/init/register/app-файлах полного списка
  type-0 переменных с ordinal и IAT-адресами не найдено; файла XEX в дереве нет.
  Поэтому предыдущий блокер полного аудита переменных ещё не снят.
- В README автор заявляет работоспособность PC и отмечает тормоза/артефакты
  Android. Это заявление автора, **не наша проверка запуска и прохождения**.
- В просмотренном дереве отсутствует файл общей лицензии LICENSE/COPYING.
  Поэтому исходные реализации не копировались. Происхождение и условия
  отдельных SDK/SDL-файлов необходимо проверять отдельно перед заимствованием.

## Полезные направления, но не патчи для слепого применения

1. **Повторное ожидание завершённого потока.** `join-once.patch` описывает
   повторный `pthread_join`. В нашем `GuestThreadHandle::Wait` ожидание завершения
   отделено от join в деструкторе; перенос POSIX-патча SDK сюда не требуется.
2. **Диагностика VdSwap.** Основной SDK-патч выводит format/color-space,
   размеры, endian, tiling, swizzle и fetch words. Это полезный набор данных для
   сопоставления настоящих кадров с нашими resource-conversion тестами, но
   чужой swap/command-processor нельзя подставить вместо нашего Vulkan backend.
3. **Асинхронный XAM content.** Патчи добавляют логи синхронного/OVERLAPPED пути.
   Их наличие не реализует отсутствующую у нас семантику async content.
4. **Не переносить tolerant-dispatch.** Патч разрешает при переменной окружения
   логировать неизвестный вызов и возвращаться. Это может скрывать ошибки
   управления потоком; такой обход не делает импорт реализованным.
5. **Не переносить D3D12/DXBC-путь.** Значительная часть основного SDK-патча
   относится к нему. Наш проект остаётся Vulkan/SPIR-V-only.
6. **Не считать ответ «успех, пользователей нет» полноценным XAM.** Патч
   `XUserFindUsers` обнуляет результат как обход падения. Сначала нужны ABI,
   допустимые состояния пользователя и проверки, а не принудительный успех.

## Вывод

Репозиторий полезен как независимый источник адресов и описаний проблем. Уже
получена дополнительная регрессионная проверка PPC без новой зависимости.
Но он не предоставляет в просмотренных файлах независимый от Rexglue готовый
kernel/GPU runtime. Полнота импортов, настоящий кадр и прохождение по-прежнему
должны подтверждаться отдельно. `Audit-Imports.cmd` остаётся способом получить
недостающую таблицу переменных из установленного XEX без запуска игры.
